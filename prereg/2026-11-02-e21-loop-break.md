# E21: break the malformed-edit loop (prereg 2026-11-02, before any E21 run)

## Observation
`reports/research-2026-11-02/judge1.md` §A, rebuilt from raw logs: malformed `edit_file` calls lose `old_string`. Onset is 5-10%, then P(bad | previous bad) is 80/86 (e18), 23/31 (idris24), 507/561 (e2b); after a good edit 4/70, 1/44, 22/698. They cost e18 6.5% of LLM calls and 6.2% of wall time, and no tool-call budget. Compaction alone lowers repeats only to 27/42. `run_command` is nearly immune (1 odd of 589), and the shell escape already solved beniget_121 and 11 e2b attempts. Never-landed unsolved attempts are 2.4% of e2b; within-task −7.1 points (59 tasks, p 0.022, post hoc); judge2 finds no consistent solve signal for any-malformed (+3.5, −4.0, 0).

## Hypothesis
The model keeps resending because the bad call stays in history as its own example. A rule tied to the exact error text moves it to a tool whose one string argument the parser does not lose. This saves time and rescues the few attempts that never land an edit.

## Assumptions
1. The model obeys a rule triggered by a visible error (rules are weakly followed, kb/index fact 4; this is the risk). 2. Scripted replacement is correct often enough. 3. The parser and error text are the same on Kaggle (starter uses `tool_call_parser='gemma4'`, same vllm wheel; no Kaggle trace confirms it). 4. The rule's added prompt tokens are negligible.

## Arms
agent_e18 (control) vs agent_e21 (e18 + one bullet under the edit rule). Base is e18 because it leads after rb r1; if pass 2 rejects e18 this still compares the rule alone. rb64 × 2 + OOD-45 × 2, interleaved, graph mode.

## Predictions
| Counter | e18 | e21 |
|---|---|---|
| P(bad | previous bad), edit tools | 93% (80/86) | ≤ 50% |
| Bad edit calls per attempt, rb | 1.4 | ≤ 0.8 |
| Local wall time, rb | − | −2% to −6% |
| Attempts with bad edit and no source change | 7/64 (forensics) | ≤ 4/64 |
| Solved | − | rb 0 to +1.5, OOD 0 to +0.5 |

## Decision
Stop after one rb pass if P(bad | previous bad) stays > 70%: the rule is not followed, so reject on mechanism. Otherwise after all passes: adopt at pooled ≥ 0, OOD ≥ −1, tokens per attempt not above control +3%, counter met. This is a hygiene rule, so a time saving with no solve loss is enough; a solve claim needs pooled ≥ +2.0 and p ≤ 0.15. Reject at pooled ≤ −1.5.
Falsifier: counter met and time unchanged, or solves fall (the shell scripts introduce wrong patches; count scripted edits ending wrong).
