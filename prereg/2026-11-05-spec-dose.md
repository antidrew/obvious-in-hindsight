# Spec dose-response (2026-11-05, before any run)

**Instrument. Adopts nothing; gold-derived data never ships or trains** (same firewall as `2026-11-03-oracle-ladder.md`).

## Observation
- The ladder (`agent_e18`, F51): control N32 1.0 / M19 12.5; O2 location 2.0 / 13.0; O3 full tests 12.5 / 15.5.
- Blind tests from a strong model: 4/28 against 0/28 on 14 flips, moto and msal only (`kb/experiments.jsonl`, O3b-solver). So what O3 supplies is largely not recoverable from the issue, even by a stronger model.
- `reports/rethink-2026-11-02/o3-contract.md` could not separate reading tests from running them: "observational; reading and running were never separated".

## Question
How much acceptance information, and in what form, buys how many solves? This matters outside the competition: in a real workflow a person can supply a sentence or one test. The curve says what that person's effort is worth for a small model.

## Assumptions
1. Fifty-one tasks and two passes are enough for N32. Arm SD is 2.2-2.4 per pass at these rates, so SE is about 1.6 with 2 passes; a difference below about 4 on N32 is not separated.
2. The prose writer is blinded to the gold patch, but sees the issue and the tests. It stands in for a developer who knows the required behaviour. It is not a measure of real developers.
3. D2's hunk is chosen mechanically, not as the most informative one, which leans low; single-hunk patches give all of O3's test content, which leans high. Both are reported.
4. N32 can only regress upward (selected on rates); the live control absorbs part of that.
5. O3 and O2 reference passes come from the same job, so they are interleaved only for pass 1. Earlier O3 and O2 passes are pooled and labelled as earlier.

## Predictions (N32 / M19, mean per pass; control about 1.0 / 12.5)
- **D1:** N32 1-3 / M19 12-14. Names carry little.
- **D2:** N32 6-11 / M19 13-16. 29 of 51 test patches have one hunk, so D2 gives those tasks all of O3's test content (without the failing-test names); the real dose contrast is on the other 22, and D2 is also read there separately.
- **D3:** N32 3-8 / M19 13-16.
- **O3 r3:** N32 9-14, consistent with 12.5.
- **O2 r2:** N32 at most 4, consistent with 2.0.

## Reading rules (fixed now)
Tested on N32 first, by one-sided within-task permutation against this job's control.
1. **Small dose works:** D2 or D3 N32 ≥ +4 and p ≤ 0.05. "A sentence or one test from a person buys a large part of the O3 gain."
2. **Prose vs executable:** D3 within 2 of D2 supports "seeing the content, not running it" (o3-contract section 3). D2 at least 4 above D3 supports "executable form matters"; report both as associations of form, since D2 also carries more content.
3. **Dose fails:** D2 and D3 both ≤ +2: the O3 gain needs the whole test patch, so the contract is not cheaply statable. Report it as such.
4. **Replication:** O2 r2 N32 above 4 reopens the location conclusion in the paper. O3 r3 below 7 means the O3 estimate is overstated; pooled numbers go in the paper either way.

## Mechanism and validity checks
- `read_ladder.py` counters: section present at first call, `lost` (over 30% unreadable), done, empties, calls.
- D3 quality: count of sections naming a concrete input and expected output. No filtering of the arm on this.
- Leak check: no gold added line (outside the test patch) in any section (`build_dose_data.py`).
- Preflight is static only (`agent_e18` unchanged, already live-tested). Hash check as in `50-oracle-day1.sh`.

## Limits
Selected partition; one agent; prose by a Claude model, not developers, and written with the tests in view, so it is a best-case sentence. Nothing here supplies the contract on hidden tasks. It measures what human-supplied acceptance information would be worth.

## Addendum (before any dose run): prior work's prediction

If that transfers, D3 should fall near O3, above this prereg's 3-8. Our predictions and reading rules stay as written. D3 at N32 ≥ 9 would support transfer; D3 ≤ 5 with O3 r3 ≥ 9 would be a disagreement to report.
Wording constraint for the paper: O3b supports "partly recoverable", not "not recoverable". 4/28 (Wilson CI about 6-32%) overlaps ORACLE-SWE's +19 to +28 points.
