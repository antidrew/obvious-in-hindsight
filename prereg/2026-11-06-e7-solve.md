# E7 solve test: does the existing RFT adapter raise solves? (2026-11-06, before any run)

## Why now
- Wrong patches are contract misses, not regressions: 81-88% of wrong attempts fail only the new tests; 2-8% break existing tests (`reports/rethink-2026-11-02/wrong_patch_anatomy.py`). On H36, 20 of 46 contract misses include an interface error (a name, argument or attribute the tests expect), and 80% fail every new test (`contract_miss_anatomy.py`). Prompt-side levers from the issue are closed (D4/D5).
- What is left is the model's own guess of what maintainers want. Training is the lever that changes the guess, and Yurnero's hints point to it. Industry: RFT on a few hundred trajectories lifted 32B models from a low base (SWE-Gym; read via summaries).
- E7's adapter (`train/lora_e7`, rank 16, 162 examples from agent_e2b successes, 111 of them on always-solved tasks) was stopped by a held-out loss rule and **never got a solve test**. A loss rule is not the outcome.

## Arms
agent_e2b vs agent_e7 (= e2b + `adapter: e7`, nothing else differs), same LoRA server for both (`serve_lora.sh`, graph mode as in the spec-LoRA job), H36 (36 tasks; airbrakesv2_118 excluded at read), interleaved: e2b r1, e7 r1, e2b r2, e7 r2. About 4 h. The base server is restored after.

## Assumptions
1. e2b's prompt is the adapter's training distribution; e18 is not, so e2b is the right base. **5 H36 tasks gave E7 training examples** (`dev_sets/rb_h36_e7train.txt`: alpenhorn_226, alpenhorn_269, lkml_74, mobilus_client_18, starlette_exporter_70, all often solved). Rule 1 reads the other 30 (airbrakesv2_118 excluded).
2. Same server for both arms removes LoRA-server confounds; graph mode differs from Kaggle's eager (time read as a ratio only).

## Predictions (per pass, of 35)
e2b 5-9. e7 − e2b −1 to +2 overall; on held-out tasks −1 to +1. Time ratio e7/e2b 1.0-1.15.

## Reading rules (fixed now)
One-sided within-task sign-flip.
1. **Scale it:** e7 − e2b ≥ +3, p ≤ 0.10, on tasks without an E7 training example, and time ratio ≤ 1.15. Then RFT at scale becomes the main GPU program (more tasks, more passes, e18 base), with its own prereg.
2. **Small RFT does nothing:** held-out delta ≤ +1. Scaling must then be argued from outside evidence, and needs a data plan first.
3. A gain only on tasks it trained on is memorisation, not a lever.
