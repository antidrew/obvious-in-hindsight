# E10: test-first reproduction (required check script before the first edit), vs agent_e2b

Written 2026-10-29, before any run. Method ([kb/method.md](../../kb/method.md)): strategy = formal verification
(make the agent's own check informative) + easier precursor problem (reproduce the bug before fixing it).

## Observation
C12 (selfcheck-audit): e2b's post-edit check verdict does not predict resolution on hard tasks (RB: PASS 48%,
FAIL 50%, none 46%). Wrong patches dominate on rb64 (54/128 vs 25 empty). In e2b the check script is written after
the edit, so it is shaped by the patch (confirmation), and nothing shows it can detect the bug at all.

## Hypothesis and assumptions
H: a check written from the issue *before* the edit, that must FAIL on the unedited code, is anchored to the issue and
proven to detect the bug; rerun unchanged after the edit, its PASS is a real signal and steers the agent away from
wrong fixes. Assumptions: (a) the model follows a required, named step (kb fact 4); (b) one extra pre-edit call does
not push the first edit past the budget often enough to raise empties much (E6: empties are budget-sensitive);
(c) most issues can be reproduced in a sandbox Python snippet.

## Predictions (counters from traces; outcome from compare_ood.py)
1. Mechanism: a check script runs before the first edit in ≥ 60% of e10 attempts, and its pre-edit output contains
   FAIL in ≥ 50% of those.
2. Signal: on rb64, P(resolved | final check all PASS) − P(resolved | not all PASS) ≥ +15 points for e10
   (e2b: ≈ 0, C12).
3. Outcome: rb64 wrong patches fall (e2b 54/128 → ≤ 44/128); pooled e10 − e2b ≥ +1.5/pass over OOD-45 × 2 + rb64 × 2,
   one-sided p ≤ 0.15, OOD ≥ −1. Empties rise by ≤ 5 per 128.
Adopt if 3 holds with 1; reject if pooled ≤ 0; otherwise 2 more passes. If 1 fails, assumption (a) broke.
If 1 holds and 2 fails, the check is followed but still uninformative: verification needs a different source.
