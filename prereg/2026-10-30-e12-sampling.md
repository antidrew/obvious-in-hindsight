# E12: Gemma's native sampling (temperature 1.0, top_k 64) on agent_e10

Written 2026-10-30, before any run. Strategy (kb/method.md): knowledge transfer (outside evidence) + iterative
prompting from our own trace history.

## Observations
- Public team MUHAMMED IDRIS (Apache-2.0 dataset muhammedidris28/gemma4-agent-runs): v19 → v24 differ only in
  temperature 0.2 → 1.0 + top_k 64 (prompt byte-identical); Kaggle 0.18 → 0.24 (single draws each; ±3 tasks noise; no
  local v24 runs). v24's bundle is now forked by several 0.24 teams (leaderboard 2026-10-30: six 0.24s, one 0.29).
- Our chain era: command-running explorer sub-agents repeated one command 30+ times at 0.2 and 0.6 and worked at 1.0
  (v14, v17, v18; kb/agent-design.md archived audit). E4b (single agent, 0.6) was −1.7 (p = 0.91); 1.0 never tested on
  the single agent.
- Gemma 4's generation_config uses temperature 1.0 / top_p 0.95 / top_k 64 (vLLM log); the model is tuned for it.

## Hypothesis and assumptions
H: at temperature 0.2 the thinking model falls into repetitive reasoning/command loops on hard tasks, which wastes calls
and time; native sampling breaks loops, so more attempts reach a verified edit. Assumptions: (a) the E10 check keeps
higher-variance edits honest (an informative verifier makes diversity useful, C17); (b) top_k 64 is not already applied
server-side (if vLLM's generation_config default already applies top_k 64, only the temperature changes).

## Predictions
1. Mechanism: repeated identical tool calls per attempt fall (count from traces), and RB attempts at the 28-call cap
   fall.
2. Outcome: e12 − e10 ≥ +1.5/pass pooled over OOD-45 × 2 + rb64 × 2, one-sided p ≤ 0.15, OOD ≥ −1.
3. Time: mean task time not higher than e10 (+5% tolerance).
Adopt if 2 and 3 hold; reject if pooled ≤ 0; otherwise 2 more passes.
