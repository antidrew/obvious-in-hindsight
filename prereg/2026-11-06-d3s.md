# D3s: behaviour or names? (written 2026-11-05 after the dose verdict, before any D3s run)

**Instrument. Adopts nothing; gold- and test-derived data never ships or trains.**

## Observation
Dose (`2026-11-05-spec-dose.md`, `kb/experiments.jsonl` Dose): on N32 a 50-word statement (D3) gave 13.5 per pass against control 0.0 and full tests 18.0. Found after the run: 25 of 51 statements name a code-like token that is in the test patch but not the issue (8 also in gold added lines); 23 of 51 state a concrete input and output (heuristic). A post hoc split on N32 (prose with test or gold names 9 of 19 solved, none new 2 of 6) is too small to read.

## Question
Does the gain come from the required behaviour, or from exact names and values that the tests fix? The first is what a developer can supply before deciding the API; the second is closer to tests in disguise.

## Arm
D3s: each D3 statement rewritten by a blinded model (sees only the issue and the D3 statement; no tests, gold, outcomes) to keep the behaviour and drop every identifier, literal, message and value the issue does not contain. Same section wording as D3. The builder refuses any code-like token absent from the issue (`scripts/build_dose_data.py --prose-s`). The rewriter may drop behaviour along with names; I check by reading 10 pairs before the run and report them.

## Assumptions
1. Removing names also removes some behaviour that names carry (an error message is part of a contract). D3s is a lower bound on "behaviour only".
2. Same F51, agent_e18 unchanged; new day, so a live control in this job; D3 rerun in the same job.
3. Two D3s passes: SE about 1.6 per arm; differences under about 4 are not separated.

## Job (`queue/pending/80-d3s.sh`, after H36; tag dose20261106; about 5 h)
Control r1, D3s r1, D3 r1, D3s r2.

## Predictions (N32 per pass)
Control 0-2; D3 11-16; **D3s 6-11** (I expect names to carry part of it).

## Reading rules (fixed now)
One-sided within-task sign-flip, N32 first.
1. **Behaviour carries it:** D3s within 3 of D3 (this job's) and D3s − control ≥ +6, p ≤ 0.05. The paper may say "a short behavioural statement".
2. **Names carry much of it:** D3 − D3s ≥ +5, p ≤ 0.05. The paper says the gain needs the exact interface and values; the "person writes a sentence" framing is withdrawn.
3. In between: report both numbers, claim only "a short exact statement".

## Before the run (11-05): data check
- Rewriter (blinded subagent, saw only the 51 issue + D3 files) wrote `research/oracle/d3s_prose.json`, median 43 words, max 50. Builder check passes after two fixes to the checker itself (trailing sentence dots, "e.g.", plurals such as DataFrames); numbers are now checked too, but a short number like 1 is matched anywhere in the issue, so that check is weak.
- Statements naming a test-patch token absent from the issue: **D3 26 of 51, D3s 0.**
- Ten random pairs read: behaviour kept in all ten; identifiers that are in the issue stay (e.g. zonal_mean, AI.FORECAST); some concrete values stay where the issue has them, and some examples became vaguer ("a standard client-error code"). So D3s removes names more than it removes values, and the contrast is narrower than "behaviour vs exact contract".
