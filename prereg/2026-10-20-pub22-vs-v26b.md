# Pre-registration: public budget-aware bundle (agent_pub22) vs agent_v26b, dev40 x 2

Written 2026-10-20 before any run.

## Why
Leaderboard (3,285 teams): the public LB has 58 tasks (1 task = 0.017). The modal team scores 0.17
(10 tasks); 32 teams show 0.22, which is the best draw of public bundles whose identical-file
draws were 7, 9, 11 and 13 (mean ~10 = 0.17). Our files average ~8 (0.15, 0.13 for v6; 0.12 for v8
and v16). So we are ~2 tasks behind the public best on the same scorer.
The bundle differs from v26b in: one agent; thinking 4096 with include_thoughts (v26b root and
explorer have thinking off; a public ablation reports thinking off 48 -> 23 / 129); 28 calls /
8 min / 240 s; "edit a source file by call 12". The harness grades the working tree when
submit_patch is never called (agent_runner.py:1054-1078), so an early edit protects against
timeouts.

## Hypothesis
H1: the gap is a real agent difference that our local evaluation can see.

## Predictions (alpha 0.1, one-sided)
- Outcome: pub22 mean dev40 >= v26b mean + 2 (v26b history: 17, 16).
- Mechanism counter: pub22 empty-patch rate <= 10% (v26b: 19% on focus16).
- Runtime counter: pub22 median agent seconds per task recorded, for the Kaggle 12 h projection.

## Reading the result
- H1 holds: adopt the single-agent shape as the new base; port v26b's working parts onto it.
- pub22 roughly equals v26b locally (within 1): local dev40 does not see the Kaggle gap. The
  suspected cause is Kaggle speed (more timeouts with no edit); check timeouts-without-edit in
  v26b vs pub22.
- pub22 is clearly worse locally: the public scores are draws, or our local set (rich-heavy) is
  unrepresentative.
